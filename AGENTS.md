# Istruzioni per gli assistenti AI

Questo repository contiene il sito dell'Associazione Pensionati Migros Ticino. Lavorare con prudenza e spiegare sempre le operazioni in italiano, con parole semplici.

## Attività comuni

- Per cambiare testi, controllare prima i file Markdown esistenti e modificare il file più pertinente.
- Testo della home page: `content/_index.md`.
- Notizie: `content/notizie/`.
- Album fotografici: `content/foto/`, una cartella per evento con un file `index.md` e le relative immagini.
- Altre pagine informative: controllare `content/associazione/` e i file Markdown nella cartella `content/`.
- Mantenere la struttura, il design, l'accessibilità e le funzionalità esistenti, salvo richiesta esplicita dell'utente.
- Non inventare date, luoghi, informazioni o didascalie. Se mancano dati indispensabili, chiedere all'utente.
- Non eliminare contenuti e non modificare file non pertinenti senza averlo spiegato e aver ricevuto conferma.
- Prima di aggiungere immagini, controllare che i file siano disponibili e che i percorsi siano corretti.
- Dopo le modifiche, verificare per quanto possibile che i file e la struttura siano coerenti e spiegare eventuali controlli non eseguiti.

## Conferma obbligatoria prima di commit e push

**L'AI deve sempre chiedere una conferma esplicita prima di eseguire un commit o un push che contenga modifiche al sito.**

Procedura obbligatoria:

1. Preparare le modifiche richieste senza pubblicarle.
2. Spiegare chiaramente quali file verranno modificati e quale sarà l'effetto sul sito.
3. Mostrare un riepilogo o una diff delle modifiche, quando disponibile.
4. Chiedere all'utente una conferma esplicita prima del commit e del push.
5. Attendere la risposta. Procedere con commit e push solo dopo una risposta affermativa riferita a quelle modifiche.

La richiesta iniziale di cambiare o aggiungere contenuti **non** vale come conferma per pubblicarli. La conferma deve essere separata e successiva alla presentazione delle modifiche.

Se l'utente non conferma, non fare commit, push né altre operazioni che pubblichino le modifiche. Lasciare il lavoro non pubblicato e attendere istruzioni.

Se un ambiente o uno strumento unisce automaticamente modifica e commit, non usarlo per pubblicare prima di avere ricevuto la conferma esplicita. Non dichiarare mai che una modifica è stata pubblicata se non è stato verificato.
